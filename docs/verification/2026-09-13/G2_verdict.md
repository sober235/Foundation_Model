## 1. 为什么不过：退化几乎没伤到解剖

nnU-Net 在留出扫描上的 Dice 与预测结构相对干净图的质心位移：

```
$PY docs/verification/2026-09-13/nnunet_by_view.py
```

```
view       patellar  femoral  tibial med  tibial lat  menisc med  menisc lat   mean
clean         0.886    0.873       0.852       0.858       0.845       0.839  0.859
noise_q3      0.885    0.871       0.851       0.856       0.843       0.837  0.857
us16          0.862    0.854       0.843       0.847       0.817       0.814  0.839

质心位移（mm，中位 / 90 分位）： noise_q3 0.119 / 0.285    us16 0.464 / 1.118
```

16 倍欠采只掉 2 个点的 Dice、挪 0.46 mm。作为尺度参照：旧 dicom-track 分割与校正版的偏差（09-11 实测）中位就有 0.3–0.9 mm、最大 3.8 mm——**标签集本身的误差比我们造的最强退化还大**。

nnU-Net 是在退化视图上训的（1860 例 = 干净 ×6 + 六档退化），所以它对这些退化本来就稳。

## 2. 更深的问题：这个任务对解剖质量本来就不敏感

同样 93 个扫描、干净视图，只换解剖来源：

```

```


Dice 从 0.86 砍到 0.40，绑定错误率只从 2.2% 涨到 6.7%（+4.5 个点）。而且 **nnU-Net 的预测分割比真值分割还好用**（2.2% vs 3.4%）——预测掩膜更平滑规整，类别受限的查表反而更稳。

## 3. 要多大位移才能让门响

直接施加病灶与解剖的相对位移（每个病灶 16 个随机方向，种子 0，真值解剖）：

```
$PY docs/verification/2026-09-13/displacement.py
```

```
 shift (mm)  wrong host  over clean   gate (+0.05)
        0.0       0.042      +0.000
        1.0       0.044      +0.003
        3.0       0.064      +0.023
        5.0       0.090      +0.048
        8.0       0.128      +0.086   fires
       12.0       0.158      +0.116   fires
```

门需要 **5–8 mm 的相对位移**。我们最强的退化给出 0.46 mm，差一个数量级。

结构性原因：类别限定之后候选本来就隔得远。半月板撕裂只能落在内外两个半月板之间（相距约 40 mm），软骨病变的四个候选之间隔着关节间隙。候选间距远大于任何现实退化造成的误差。

## 4. 这对方案意味着什么

方案的前提是"退化让几何查表失效，关系模型来挽救"。在 SKM-TEA 膝关节 + 类别受限候选这个设定下，前提不成立：几何查表本来就很难被采集退化打垮。

运动仿真（§13.6 里 G2 不过的既定下一步）大概率也救不回来：膝关节 5 分钟 qDESS、腿固定在线圈里，典型运动是亚毫米到两三毫米，达不到 5–8 mm；真到 5–8 mm 的扫描临床上会重扫。

已经确定的事实（都可复跑）：
- 类别感知查表在干净数据上的天花板 0.958（真值解剖）/ 0.961（nnU-Net 解剖）。
- 解剖质量减半，绑定错误率只动 4.5 个点。
- 采集退化（噪声三档、欠采三档）对绑定错误率的影响在统计上为零。
- 从零训的病灶检测头在 124 卷上不泛化（09-12）。

## 6. 补充（同日）：分割模型分布外也救不回来

第 1 节留了一个口子：五折 nnU-Net 的训练集里一半是退化图，它对退化稳可能只是因为学过。于是加训一个只看干净图的模型（Dataset901 的 fold 5，训练集 = fold 0 那 124 个训练扫描的 744 个干净例，测试集不变，仍是 31 个留出扫描 × 7 个视图），它从没见过退化图。

```
source scripts/nnunet_env.sh
CUDA_VISIBLE_DEVICES=1 nnUNetv2_train 901 3d_fullres 5 -tr nnUNetTrainer_250epochs
$PY docs/verification/2026-09-13/probe_gate.py
```

```
view       Dice 只训干净  Dice 训过退化  相对自身干净图的位移 mm  组织族错
clean            0.861          0.861                      -     0.052
noise_q3         0.859          0.860                  0.141     0.052
us8              0.835          0.851                  0.616     0.052
us16             0.785          0.841                  1.019     0.069

判定：不通过（n=58 个病灶、22 个扫描，只有 fold 0 的留出集）
```

分布外确实更脆：16 倍欠采下 Dice 掉 5.6 个点（0.841 → 0.785），位移翻倍（0.46 → 1.02 mm）。但绑定错误率只涨 1.7 个点。

对照第 3 节的位移曲线，这是自洽的：位移翻一倍换来约 2 个点。门要 5 个点，需要 5 mm 上下的位移，也就是还差五倍。**让分割模型分布外，只买到 2 倍，需要 10 倍。**

## 9. 余量由什么决定：病灶尺度与类别限定

```
$PY docs/verification/2026-09-13/size_vs_margin.py
```

```
膝，真实病灶，类别受限            0.5   1.0   2.0   3.0   5.0   8.0  mm
  小的三分之一（边长 7 mm）      0.010 0.011 0.024 0.047 0.075 0.109
  大的三分之一（边长 22 mm）     0.007 0.008 0.018 0.032 0.054 0.092

   边长 3 mm                     0.000 0.117 0.195 0.258 0.381 0.503
   边长 6 mm                     0.069 0.069 0.141 0.203 0.313 0.462
  边长 24 mm                     0.019 0.019 0.046 0.073 0.128 0.209
```

膝侧病灶大小几乎不影响余量——类别限定压倒一切。脑侧没有类别限定，尺度就起决定作用：边长 3 mm 的病灶，1 mm 位移就有 11.7% 改判宿主，是膝侧同位移下的十倍。

而 1 mm 位移是够得着的：第 6 节里只训干净图的分割模型在 16 倍欠采下就位移 1.02 mm。

也就是说，**存在一个能激活这个科学问题的配置：小病灶 + 无类别限定 + 结构密集的器官**。它的障碍不在物理，在真值——脑侧没有标注者指定的"病灶属于哪个结构"，只能拿干净图上的答案当参照，主张就从"更准"退化成"更一致"。
