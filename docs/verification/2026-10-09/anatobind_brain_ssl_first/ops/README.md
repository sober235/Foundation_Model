# 运维脚本存档（2026-10-10，原件在会话 scratchpad，路径写死当晚的配置）

本机是共享卡：卡一空出来一两分钟内就会被别的会话或用户占走（记忆 never-release-held-gpus）。下面这些脚本只管"卡不空出来"与"中断后接着跑"，不碰训练本身。

| 文件 | 做什么 | 当晚用在哪 |
|---|---|---|
| `hold_card.py` | 在一张卡上占 4 GiB，等旧进程退出、新任务占满后 30 s 自退 | 15:33 C0 换 32 个加载进程时守 5 号卡 |
| `swap_c0_v2.sh` | 等 C0 第 3500 步存盘写完 → 占位 → 停旧链 → 换链脚本 → 同卡续跑 | 同上 |
| `hold_c2.py` | 第二轮还在跑时就在 0、2 号卡占位，守到 C2 正式 Stage II 记下第一步；第二轮或 C2 链报失败即放 | 16:32–19:33（第二轮中止时按规则放掉） |
| `hold_multi.py` | 立即在几张卡上占位，等它们都被新任务占满后自退 | 19:34 第二轮中止后守 0、2、3 号卡直到续跑占满 |
| `r2_watchdog.sh` | 第二轮再被中止就占卡并从最新存盘续跑（最多 3 次）；第 8800 步起启动 `hold_c2b.py` | 19:49 起，tmux `r2dog` |
| `hold_c2b.py` | `hold_c2.py` 的续跑版（盯最新的续跑链日志） | 由看门脚本在第 8800 步启动 |
| `card_guard.py` | 链活着时，卡上链自己的任务低于 20 GB 就补占 4 GiB，任务占满 30 s 后放；链结束即退 | C0（5 号卡，tmux `guardc0`）；C2（0、2 号卡，由 `guard_c2_launcher.sh` 在 C2 链起来时启动，tmux `guardc2`） |
