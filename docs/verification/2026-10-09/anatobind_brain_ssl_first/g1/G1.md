## 结论与出路（2026-10-09 晚的读法；机制部分已被下面的"更正"取代）

1. Stage I 训练本身收敛且健康（验证 masked Huber 0.366 → 0.037，有效秩 56.8），**但在 G1 的口径下不过，微调探针也看不到优势**。原因在目标设计：遮挡重建把中间层塑成重建强度的形状、不留线性可读的解剖/位置信息；全局 InfoNCE 的正样本定义强加了强度不变性。
2. G1 的随机臂有位置捷径（局部坐标嵌入直通），门的口径本身偏向随机初始化；但把位置全去掉随机仍领先，所以不能把不过关归咎于口径。
3. 出路（用户拍板，STATUS.md §2 第 0 条）：(a) 先跑 C0（随机骨干的 Stage II → III → 评估）保周四的 A/U/R 结果与对照臂；(b) Stage I 修复一轮：对比项改稠密同位置对比、正样本不用强度增广而用不同遮挡、加不遮挡视图份额；(c) 并行则各慢一倍。


## 更正（2026-10-10 03:xx 本机）：根因是代码缺陷，不是目标设计

上面"遮挡重建把中间层塑成重建强度的形状"的读法在机制上是错的。读代码确认：`anatobind/aur/ssl/model.py` 的 `StageOne.view` 把 `levels[0]["feat"]`（F1，第一层输出）交给重建解码器 `MaskedPatchDecoder`，解码器只读 F1。F1 只依赖 patch stem、局部坐标嵌入和第一层的 2 个 Swin 块；第一层之后的 PatchMerging 与第 2–4 层（12 个块里的 10 个）**从来没有收到重建梯度**，只被权重 0.1 的全局 InfoNCE（F4 池化，批内准确率全程 1.0）训练过。这与诊断完全吻合：F1 单层读出接近随机（0.265 对 0.283），只靠对比项训练的 F2 最差（0.171 对 0.295），且从第 500 步起就低于随机。我在 T04 实现与评审时都没发现这一点（计划原文就写"从 F1 解码"，没人追问梯度到不到深层）。

修复（第一轮，提交 61b915a）：解码器读全部四层（每层 1×1×1 投到 64 通道，自 F4 向 F1 逐级三线性上采样相加，再两层 1×1×1 预测每个 F1 patch 的 2×4×4 体素），只读各层特征、不读输入图像，被遮体素依然够不到。新测试：只用重建损失反传时骨干每一层（含 PatchMerging）梯度非零（旧代码在此挂）；重建输出对被遮体素的改动不变。全尺寸模型在一个真实裁块上 CPU 前向反向通过，四层梯度 L1 分别 40 / 82 / 226 / 92，解码器 6.8 万参数。

## 第一轮预先登记的修订（2026-10-10 03:3x 本机，独立评审之后、任何运行开始之前）

评审（`reviews/stage1-r1-review.md`）认为解码器修复正确、无泄漏、是公平的单变量改动，但原定的提前规则在单种子噪声下会误停。修订如下，取代上面"第一轮的预先登记"里的探针与规则两条：

- 提前探针改用 3 个种子（0 1 2，读出头的初始化不同，裁块相同；单种子噪声约 0.003）。
- **停止规则**：仅当第 2000 步 Stage I 读出 < 随机臂 − 0.01，**且**自第 1000 步起上升 < 0.01 时停；其余情况都继续（包括低于随机但在明显上升、或与随机持平）。理由：第一次运行在 18k 曝光时已低于随机 0.08 且一路下降，这个规则足以抓住同类失败，又不会把仍在学的运行误停；两次探针预测不了 G1 能否通过，只用来止损。
- 探针失败（显存、崩溃）重试一次，再失败就跳过、不影响训练（原链会因此杀掉训练）；探针卡必须在训练卡之外；只允许 3 张或 6 张训练卡（每个 micro-batch 的 InfoNCE 覆盖 36 个裁块，与第一次相同，否则是第二处改动）。
- 每次探针在 CPU 上记录归因（`scripts/aur_ssl_attrib.py`）：骨干各部分（stem、各层 blocks、各 merge）重建梯度与 0.1×对比梯度的 RMS，以及解码器读全部层 / 只读 2–4 层 / 只读 F1 时的遮挡重建损失。
- **第二轮的单一改动按第一轮第 2000 步的归因选**：若第 2–4 层 blocks 的"重建 / 对比"梯度 RMS 比的中位数 < 1（深层仍被对比项主导）→ λ_c = 0；否则 → 解码器去掉 F1 那一路（只读 2–4 层，强迫深层承担重建）。两轮都不过交用户。

评审的实测（CPU，12 个真实裁块、6 个患者）供对照：修复后的模型在初始化时 0.1×对比的梯度 RMS 是重建的 3–5 倍（各层都是，InfoNCE 在随机权重上准确率已 1.00）；第一次运行第 2000 步时对比项流入第 2–4 层的梯度已降到 1.3–2.9e-5，第 1 层重建 ≈ 对比（比 0.96）。

其他披露：
- **遮挡布局携带前景轮廓**（既有问题，`masking.py`）：块只在前景 patch 上遮，块内背景 patch 保持可见（−1），所以"哪些 patch 被遮"本身告诉模型那里有组织。不泄漏强度，只泄漏被遮区域的前景轮廓；本轮不改（改了就是第二处改动），留到之后。
- **无学习基线改了口径**：原基线把可见的背景（−1）也平均进预测，太容易打败；现改为只用可见前景体素的均值（`heads.interpolation_baseline`）。第一次运行日志里的 `mim_baseline` 0.361 是旧口径，因此"0.366 → 0.037"高估了训练健康程度；第一轮日志用新口径。
- **F1 自己就能补全大部分**（评审实测）：真实验证裁块上，没有一个被遮 token 在第一层窗口注意力可及范围（约 16×64×64 mm）内找不到可见 token。所以 F1 那一路能单独完成局部插值，深层只学 F1 解释不了的部分；这正是第二轮"去掉 F1 那一路"候选的理由。
