## 2. 为什么不过：模型没把小病灶分出来，不是后处理

- **阈值**：上限 0.394 @ 4.3 FP/卷（§1）。
- **解码**：不用 argmax 而按概率 p ∈ {0.5, 0.3, 0.2, 0.1} 取候选（`decode_variants.py`），≤ 2 FP/卷下大类灵敏度 0.25–0.27，上限最多 0.458 @ 6.1 FP/卷。漏掉的病灶在概率图里就不存在。

```

 0.20 | 0.55 | 0.314 | 0.269 | 1.81 | 0.441 @ 5.33

```

- **训练信号**：折末伪 Dice 软骨 0.10–0.14、半月板 0.05–0.18、韧带 0.10–0.27、积液 0.54–0.66（`results/fold_k/training_log_*.txt`）。箱填标签对大病灶（积液）够用，对最小三分位（软骨 < 1.8 mL、半月板 < 0.4 mL，即边长 3–12 mm）几乎学不到：每折只有约 82 个半月板撕裂、166 个软骨病变当训练例，且方框边界不是病灶边界。
- **与 09-12 的对照**：自研热图头留出定位召回 0.57 但分数不可用（任何阈值都没工作点）；nnU-Net 箱填法留出 0.28–0.39 且分数可用。两条路都离"大类正确 ≥ 0.5 @ ≤ 2 FP"很远。

## 4. 第二臂的选项（由用户定，本计划到此为止）

1. **fastMRI+ 膝预训练的 2.5D 检测器再迁到 SKM-TEA**（计划 Q9 的备选臂 (c)）：16 167 个框、969 卷，标注量是 SKM-TEA 的 35 倍；前提是 v2.6 的 Gate 0（框上下翻转修复）和 H1 重跑，这两件事计划 3 本来也要做。风险：2D PD TSE 冠状位到 3D qDESS 矢状位的域差。约一周。
2. **nnDetection（Retina U-Net 3D）直接训 SKM-TEA**：专为框设计的检测器（anchor + focal loss + 难负例），2–3 天含安装；样本量不变（465 框），只能回答"是目标函数的问题还是数据量的问题"。
3. **nnU-Net 换目标继续挤**：单一"病灶"类 + 1000 轮 + 提高前景块采样比例。最便宜（一天），但 §2 的训练信号说明上限不高。
4. **接受现状转入脑侧（计划 2）**：膝的目标 2 记为"积液与大病灶可用、小病灶未达标"，脑侧的目标 2 是有 3D 掩膜真值的分割任务，不受这个问题影响。

我的推荐：先做 1 的前半段（Gate 0 + fastMRI+ 膝上 H1 重跑，1–2 天）——它本来就在计划 3 里，而且能先回答"16k 框训出来的检测器能不能到可用工作点"；能到就迁到 SKM-TEA，不能到再上 2；两者都不行就按 4 处理。
