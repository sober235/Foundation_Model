# 脑侧小病灶检测线（fastMRI+ 小病灶）：两条臂都没过门，先停（2026-09-30，用户批准）

这一页只汇总已有记录里的数字并说明为什么停，不含新的实验。数字的出处是两份记录索引：
`docs/verification/2026-09-28/brain_detector/README.md`（S2，nnU-Net）与 `docs/verification/2026-09-29/brain_nndet/README.md`（第二臂，nnDetection）。

## 任务与门

Dataset903：fastMRI+ 的 253 卷 FLAIR（165 卷有病灶、88 卷正常），1297 个三维小病灶（两种小病灶标签、边长 ≥ 3 像素的框填成掩膜），患者级五折。
门 D1：3D 框 IoU ≥ 0.1 一一匹配，每卷假阳 ≤ 2 的阈值里灵敏度最高的一行 ≥ 0.5。

fold 0 的配对表（各自工作点）：两者都中 11、只 nnDetection 6、只 nnU-Net 2d 81、都漏 182。nnDetection 在 0.05 阈值下能找到 178/280，代价是每卷 29.9 个假阳；0.005 步长的细网格里预算内最好也只有 40 个命中。

## 为什么停，而不是继续调

1. 两条臂失败的方式一致：主因是漏检，不是阈值。nnU-Net 的解码范围只碰到每卷 1.7 个假阳就到头，nnDetection 要付每卷 5 个假阳才追平 nnU-Net 的命中数。
2. 漏检集中在单层小病灶：1297 个病灶里 1029 个只占一层；S2 2d 五折上单层 346/1029 = 0.336、多层 129/268 = 0.481（`brain_detector/2d/REPORT.md` 的 Number of Slices 分层）；nnDetection fold 0 上单层 7/222、多层 10/58，且重采样到 5 mm 后 3 mm 层厚卷里 20 个单层病灶有 8 个直接从训练标签里消失。问题在标签与数据表示（单层框、层厚不一），换模型不解决。
3. 标签本身有噪声：61 个卷里 819 个 fastMRI+ 框（Nonspecific lesion、Craniotomy、Dural thickening 等）没有填进标签，在训练里是背景，模型若在那里检出就记假阳（S2 的 D10）。
4. 规则 A 是用户开跑前定的判断线（fold 0 命中 ≥ 同折 2d + 0.05 × 280），不过就停、不补五折、不调参救门（S2 的 D9、S7 的 M5）。

## 如果以后再捡起来

要先换规格，不在这一线的范围内：a）标签层面——把 819 个未填的框处理成"忽略区"而不是背景，或只保留多层病灶；b）表示层面——按原生层厚（3 mm / 5 mm）分开训练，不把 3 mm 卷重采样到 5 mm；c）读片层面——医生的 Level R 标签出来后，用它而不是 fastMRI+ 的框当真值。
本仓库里可复用的工具：nnDetection 的环境与 runner（两环境只用 JSON 交接）、真值当预测的坐标检查（已加"回来的实例里 IoU ≥ 0.99 的占比 ≥ 0.8"的判据）、S2 格式的评估与配对表。
