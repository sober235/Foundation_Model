# Leg 2 设计：fastMRI+ 膝关节的病灶检测与重采闸门

**日期**：2026-09-14　**状态**：待用户审阅　**上游决策**：本文件末尾的"为什么是这个设计"

## 0. 目标与范围

用户 2026-09-13 给出的核心目标，原话拆成五步：

1. 认识解剖结构
2. 认识病灶是什么病
3. 病灶在图像上什么空间位置
4. 病灶在什么解剖结构上
5. 轻微退化下 1–4 仍然成立；退化过于严重时判定"图像污染过重"，发出重新采集的要求

按数据可得性，这五步落在两条互相独立的腿上：

| | 第一条腿（SKM-TEA） | 第二条腿（本文件，fastMRI+ 膝） |
|---|---|---|
| 覆盖的步骤 | 1、4，以及 1/4 的退化稳健性 | 2、3、5 |
| 状态 | 已完成，见 `docs/verification/2026-09-13/G2_verdict.md` | 全新 |
| 数据 | 155 卷，465 个框（分割内 311），6 组织分割真值，宿主真值 | 974 卷 / 509 患者，16154 个框，原始多线圈 k 空间 |
| 没有的东西 | — | 解剖分割真值、宿主真值 |

用户 2026-09-13 确认接受这个分工：两条腿各自验证，不要求任何单一数据集端到端跑通全链路。本文件只覆盖第二条腿。

**范围之外**：解剖分割与宿主绑定（第一条腿已完成）；跨两条腿的联合模型；运动仿真；跨器官扩展。

## 1. 数据引擎

### 1.1 来源与计数（已实测，2026-09-13）

```
/data2/congcong/data/FM_data/fastMRI_lh_brain_knee/
  kspace/knee/multicoil_train/*.h5    973 卷
  kspace/knee/multicoil_val/*.h5      199 卷
  Annotations/knee.csv                16167 行
```

每个 h5：`kspace` (slices, coils, 640, 372) complex64；`reconstruction_rss` (slices, 320, 320) float32；属性 `acquisition`（CORPD_FBK 或 CORPDFS_FBK）、`patient_id`、`max`、`norm`。层数 29–50，中位 35。

标注列：`file, slice, study_level, x, y, width, height, label`。坐标在 320×320 的 RSS 图像空间（实测 x 15–278，y 0–280），中位框 28×18 像素，按膝关节 FOV 约合 14×9 mm。

计数：1172 卷来自 **556 个患者**（513 个患者有 2 卷，即同一膝的 PD 与 PD 压脂）；974 卷有标注，来自 509 个患者；标注卷中 CORPDFS_FBK 520、CORPD_FBK 454。

### 1.2 类别

保留五个类别族，合计 15097 个框（2026-09-14 实测；本节初稿写 15087，是加总失误）：

| 族 | 框数 | 并入的原始标签 |
|---|---|---|
| 半月板 | 5890 | Meniscus Tear、Displaced Meniscal Tissue |
| 软骨 | 3600 | Cartilage - Partial / Full Thickness loss/defect |
| 骨 | 2229 | Bone-Fracture/Contusion/dislocation、Bone- Subchondral edema、Bone - Lesion |
| 韧带 | 2067 | Ligament - ACL/MCL/PCL 各级、LCL Complex 各级、Patellar Retinaculum |
| 积液 | 1311 | Joint Effusion |

丢弃：`other` 1070 个（Periarticular cysts、Soft Tissue Lesion、Muscle Strain、Joint Bodies 等，单类样本过少）、`artifact` 13 个、`study_level == "Yes"` 的 13 行（只有研究级结论没有框）。

### 1.3 清洗

实测存在退化框（`height` 最小为 0，`width` 最小为 3）。导出时筛掉 `width < 3` 或 `height < 3` 的框，并在清单里记账（照 SKM-TEA 导出的做法，数目写进 manifest）。

### 1.4 3D 病灶合并

标注是逐层 2D 框。实测同一 (卷, 类别) 组内 96% 的层间隔是连续的（连续 11348 对、跳层 436 对），中位 5 层、最多 33 层，7% 的组只占一层。

**合并规则**：在同一 (卷, 类别族) 内，相邻层（层号相差 1）的两个框若面内 IoU ≥ 0.3 则相连；每个连通分量是一个 3D 病灶，其 3D 框取各层框的外接框。同类别但空间分离的两串（如内侧与外侧半月板）因此分成两个病灶。预计合出 2600–4000 个 3D 病灶。

合并结果写进导出清单，每个 3D 病灶记录：卷、类别族、层范围、3D 框、构成它的 2D 框数。

### 1.5 划分

按 `patient_id` 五折。同一患者的全部卷（PD 与 PD 压脂）必须落在同一折，否则同一个膝会同时出现在训练与留出集。折的划分文件与 SKM-TEA 的 `splits.json` 同格式。

### 1.6 退化

干净图与退化图必须走同一个重建算子（V5 §11）。

- 重建算子 `R`：逐层、逐线圈 2D IFFT，再按线圈做平方和开方（RSS），得到 320×320（中心裁剪，与 `reconstruction_rss` 同口径）。
- 干净：`X0 = R(K)`，K 为 h5 中的全采样 k 空间。
- 噪声三档：`K + n`，`n ~ CN(0, σ² I)`，`σ = c · median(|K|)`，其中 |K| 取该卷全部非零 k 空间样本的模。三档 `c = 1, 2, 4`，记作 q1/q2/q3。c 与档位在导出时写死，不再调。
- 欠采三档：`M ⊙ K`，M 为相位编码方向的 1D 等距掩膜，加速 4×、8×、16×，中心全采比例按 fastMRI 惯例取 0.08、0.04、0.04。掩膜按卷固定种子生成，同一卷的三档掩膜互相嵌套。

七个视图（clean + 三档噪声 + 三档欠采）与第一条腿一致，便于两条腿的曲线并排。

**已知弱点**：h5 不含线圈灵敏度图，因此重建是零填充 RSS 而非 SENSE，欠采后的图带有混叠而非 SENSE 噪声放大，比第一条腿的口径弱一档。若后续需要，可先用 ESPIRiT 估计线圈图再做 SENSE；本设计不做，论文中明确写出。

### 1.7 两处必须先查清的事实

这两件事决定负样本怎么取，直接影响假阳性率与闸门标签，**在写数据引擎代码之前解决**：

1. 每卷中位只有 9 层带标注，全卷约 35 层。其余层是"已确认无病灶"还是"未标注"？决定未标注层能否作负样本。
2. 1172 卷中有 198 卷完全没有标注，是正常膝还是漏标？

解决办法：读 fastMRI+ 的方法学文献确认。若无法确认，退守方案——只用带标注的层作训练样本，某层的负类取"该层标注了别的类别族但没有本类别族"，不使用未标注层，并在报告中写明这一限制。

## 2. 模型

### 2.1 编码器：2.5D

输入为以某层为中心的 5 层薄块，张量 (B, 1, 5, 320, 320)。

- 3D stem：`Conv3d` 核 (5, 3, 3)，把深度 5 压成 1，带入跨层上下文。
- 主干：MONAI `SwinTransformer`，`spatial_dims=2`，四级层次，在 320×320 上运行。与第一条腿同一架构家族。

不用全 3D 主干的原因：只有 5 层，stem 步长 2 加三次 patch merging 会把深度降到 0；把 5 层塞进 3D 层次是与数据较劲，而第一条腿已经证明瓶颈在样本效率而非网络容量。

### 2.2 检测头

`anatobind/model/dense_head_2d.py`，是 3D `dense_head.py` 的 2D 对应：F1 网格上逐类中心热图、格内偏移 (2)、框大小 (2)、逐格 embedding。损失为热图上的 CornerNet focal loss 加峰值格处的偏移与对数框大小 L1，按目标数归一。

新写一个 2D 模块而不是把 3D 模块泛化成 dims 可配：第一条腿已冻结跑完并产出结论，为省一百行去改动它，风险与收益不对等。

### 2.3 两个可靠性头

`anatobind/model/reliability.py`。

**逐病灶头**：输入为检出框及其外扩一圈（V5 §10 的 Ω，本条腿无解剖，故只用框加外扩）在编码器特征上的池化，拼上该检出自身的标量——峰值得分、top-1 与 top-2 类别概率之差、框大小。输出该条结论正确的概率，sigmoid。

**扫描级头**：输入为全局池化特征，拼上该卷全部检出的统计（检出数、峰值得分的最大/中位/最小、逐病灶可靠性的最小值）。输出"本卷流程至少错一处"的概率。

两个头都只看单张图，不看任何干净图参照，满足无参照约束。

**为什么必须是两个**：逐病灶头只能评价检测器找到的东西，漏检对它不可见，而漏检是最危险的失败。扫描级头专门覆盖这一类。

### 2.4 训练分期

沿用第一条腿验证过的分期：

1. 训练检测器（五折，每折一个），冻结。
2. 每折的模型在**完全没参与其训练的**留出患者上生成预测并缓存。
3. 用这些折外预测得到的对错标签训练两个可靠性头。

V5 §10.1 要求折外，直接用同折训练集的对错标签会严重高估可靠性。

**折的套法**（避免二次泄漏）：五折记作 0–4。第 k 个检测器在 folds ≠ k 上训练，在 fold k 上出预测；五个检测器跑完，每个患者恰有一份折外预测。可靠性头沿用同一套划分：第 k 个可靠性头在 folds ≠ k 的折外预测上训练，在 fold k 的折外预测上评估。报告的所有可靠性数字都来自各自 fold k 的评估，不做二次选择。

## 3. 闸门

### 3.1 失败标签

在 3D 病灶级上定义（读片关心的是病灶，不是某一层）。折外预测先按 1.4 的规则合成 3D，再与 3D 真值按 3D IoU ≥ 0.1 匹配（与第一条腿同一阈值），另报 IoU 0.05 与 0.2 作敏感性。

- 逐病灶标签：每个超过检出阈值的 3D 检出，匹配上且类别族正确记 1，否则记 0。
- 扫描级标签：该卷存在任意一处错误则记 1，**漏检计入**。

**防退化情形**：若几乎每卷都至少错一处，扫描级标签会近乎全 1，无从学习。因此检出阈值先在**训练折上**调到使扫描级正样本率落入 20%–50%，该阈值随后固定，不在留出集上调。

### 3.2 聚合

扫描级判定由 2.3 的扫描级头给出。同时报告一条不学习的基线：取该卷全部逐病灶可靠性的最小值。基线看不见漏检，因此"扫描级头是否值得"成为可检验的问题，而非假设。

### 3.3 阈值

不使用 0.5（V5 §16）。在验证折上作风险–覆盖曲线，取

```
tau = min{ tau : Risk(自动接受的扫描中含错误) <= 0.05 }
```

风险目标 0.05 事先写死。

### 3.4 事先写死的判据

**H1（止损门，不是精度门）**：在 3.1 选定的工作点上，留出患者的 3D 检出数 ≥ 300，且逐病灶标签的正样本率落在 20%–80% 之间。**H1 不过则停止，不建闸门**——说明检测器要么什么都找不到、要么全对或全错，可靠性头没有可学的内容。这是 2026-09-13 G2 的直接教训：先证明后一层有东西可做。

**H2（方法门）**：**在每个退化档位内部单独评估**，逐病灶可靠性头的 AURC 低于"直接用检出峰值得分"这一基线，患者级 bootstrap（10000 次，种子 0）的 95% 置信区间不含零。跨档位合并后的胜出不计——那只说明模型学会了"图越糊分越低"（V5 §10.2、§15.3）。

**H3（目标门）**：在固定风险 0.05 下，学习得到的扫描级闸门所保留的覆盖率，高于"按加速倍数一刀切"规则（即 us8 及以上一律要求重采）所保留的覆盖率，患者级 bootstrap 的 95% 置信区间不含零。

H3 直接对应用户目标的第 5 步。它之所以可赢，是因为第一条腿已经量出退化档位与任务失败的关系很弱（`docs/verification/2026-09-13/G2_verdict.md` 第 1、2 节）。

## 4. 报告口径

- 检测：3D 病灶级召回与精度，按类别族、按退化档位分别报；PR 曲线。另报 2D 逐层口径，因标注原本即为逐层。
- 可靠性：每个退化档位内部的 AURC、Brier、ECE、风险–覆盖曲线、固定风险下的覆盖率，全部与峰值得分基线并排。
- 闸门：固定风险 0.05 下的覆盖率，与加速倍数一刀切规则并排。
- 图：沿用仓库现行约定（经校验的配色、两行视图标签、图例置于轴外、渲染后目视检查再引用）。

## 6. 测试

沿用仓库现行的行为命名与合成夹具（`tests/synth.py` 的对应物）：

- 退化框被筛掉，且数目写进 manifest
- 3D 合并：相邻层重叠的框合成一个病灶；同类别但空间分离的两串合成两个；单层组也成为一个病灶
- 划分：无患者跨折；同一患者的 PD 与 PD 压脂落在同一折
- 退化：干净与退化走同一算子；干净路径复现 h5 中的 `reconstruction_rss`（数值容差内）
- 2D 头：目标构造（中心格、偏移、对数框大小）、解码（峰值→框、类别概率）、损失（正确热图的损失显著低于错误热图）
- 失败标签：全对的预测给出全 1 逐病灶标签且扫描级为 0；人为制造一个漏检，扫描级标签变 1
- 闸门：风险–覆盖曲线单调；按 0.05 目标选出的阈值确实达到该风险
- H1/H2/H3：在已知答案的合成输入上计算，门该响时响、该不响时不响

最后一项沿用 2026-09-13 G2 脚本的做法（注入合成错误，检验门确实触发）。

## 7. 已知弱点（写进论文，不隐藏）

1. 重建为零填充 RSS 而非 SENSE，欠采后图像带混叠而非 SENSE 噪声放大，比第一条腿口径弱。
2. 第二条腿无解剖分割与宿主真值，因此用户目标的第 1、4 步只能由第一条腿覆盖；没有任何单一数据集端到端验证全链路。
3. 标注为逐层 2D 框，3D 病灶由合并规则得到，合并规则本身引入标签噪声。
4. 1.7 的两处未决事实若退守处理，负样本来源受限，假阳性率的估计会偏乐观。

## 8. 为什么是这个设计

- **为什么换到 fastMRI+**：SKM-TEA 只有 465 个框、155 卷，从零训练的检测头在留出扫描上给出 0/84（`docs/verification/2026-09-12/fold0_pilot.md`）。fastMRI+ 膝有 16154 个框、974 卷，且原始 k 空间齐备，是同一解剖。
- **为什么两条腿分开**：只有 SKM-TEA 有宿主真值，只有 fastMRI+ 有足量病灶标注；没有数据集两者兼有。用户 2026-09-13 确认接受。
- **为什么 2.5D**：fastMRI 膝为 2D 采集，层厚约 3 mm；2.5D 给出约 8800 个标注层样本，而合并后的 3D 病灶只有约 3000。上一次失败的根因是样本效率（`docs/verification/2026-09-12/fold0_pilot.md` 第 6 节），本设计优先解决它。
- **为什么闸门按任务失败监督**：用户 2026-09-13 选定。按退化档位监督会学成"图越糊分越低"，而第一条腿的测量表明退化档位与任务失败关系很弱，那样的闸门会把可用图误判为需重采。
- **为什么先写死 H1**：2026-09-13 的 G2 在投入五折训练之后才发现分析子集为空。H1 把"后一层有没有东西可做"提到投入之前。
