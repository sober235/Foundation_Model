# AnatoBind：核心目标、实际进度与后续路线

日期：2026-10-21。状态：**供用户审阅的路线建议，未替代已批准协议，未启动新实验**。

核对基线：`0c0f2f8b5efec2a25dfb65b95890d77827cad491`。本文件回应用户要求：结合前序上下文重新理解目标、判断做到哪里、建议后续顺序。本次仅整理设计，不改产品代码、数据、训练配置或既有裁决。

## 1. 我们要交付什么

交付一个脑 MRI 结构化感知模型：给它独立二维图像或三维序列体数据，输出可定位、可追溯的解剖结构 A、异常实例 U，以及每个异常所属的解剖结构 R。输入模式切换时使用同一个模型及 checkpoint。二维只依据该平面可见的信息，不借用相邻切片伪装单图能力。

这解决的是“图中有哪些结构、异常在哪里、异常属于哪个结构”。疾病分类、完整临床诊断、所有器官或所有未知疾病不是已验证能力。当前首个验收范围沿用已批准的**脑 MRI、单次一个序列、既定标签与来源**；统一异常类表示合并已标注病灶，不证明穷尽全部未知异常。用户希望最终以交互 URL 展示，但已明确模型成功优先，网页后置。

| 层次 | 已确认的内容 | 如何理解 |
|---|---|---|
| 用户功能目标 | 独立 2D 与 3D；识别解剖、找异常、说明异常所在结构 | 两个模式分别验证三项能力，不能以三维结果替代二维 |
| 已采用的输出合同 | A32 非背景结构 mask；U 通用异常实例 mask；R13 分侧宿主 + no-host | 保持身份、侧别、实例关联；未知关系不能强行变成 no-host |
| 已批准的执行约束 | SSL-first I→II→III；保留 DICOM 全部信息；显示后置；持续按顺序推进 | 没有周四截止节点，也不因进度压力绕过阶段门 |
| 当前技术路线 | 共享骨干、小型维度适配器、一个 checkpoint | 已实现并经过技术 pilot；不等于所有参数必须相同 |
| 可被实验推翻的技术选择 | query 数量、mask 参数化、SSL 配方、R 的几何来源 | 它们服务于 A/U/R，不是用户目标本身；修改须按新设计与实验登记执行 |

“可用”的意义至少包括：输出正确且有定位、能区分多个病灶、侧别可靠、误报受控、输入输出与源图像对应。只有训练 loss 降低、代码测试通过或线性探针过门，不构成这一交付。

## 2. 当前已经到哪里

### 2.1 可以继续利用的资产

- 数据审计、安全离散标签解码和新数据合同已完成。35 份 TRAIN 与另 3 份开发验证 ISLES 阳性标签在新版本恢复，旧版本和失败证据保留。
- 新合同有监督 TRAIN 3499 行 / 894 个来源限定患者，SSL TRAIN 5501 / 1895，开发验证 405 / 101。清单身份互斥不等于跨来源生物学去重已证明。
- 统一 2D/3D 架构、数据适配、恢复、完成证书和双模式 G1 已实现。此前小模型 TRAIN pilot 与全尺寸资源 probe 均有记录，不需要为证明相同执行能力再跑一遍。
- 新统一 Stage I 从既有三维 SSL step8500 权重 warm-start，复用 176 个张量、固定种子初始化 4 个二维张量，完成 2048 步，两模式各 1024 次新曝光。它不是从零预训练，亦不是旧训练状态的 exact resume。
- best 按登记的验证 loss 选在 step1792；独立完成证书记录实际训练到 step2048。CPU 回归的既有记录为 1699 passed / 5 skipped，本次路线整理没有重跑测试。

### 2.2 最新阶段门

| G1 工程读出指标 | 2D | 3D |
|---|---:|---:|
| 宿主 Dice：训练后 / 随机骨干 | 0.279637 / 0.236092 | 0.714408 / 0.364809 |
| 增益，门为至少 0.05 | 0.043545 | 0.349600 |
| 判定 | FAIL | PASS |

二维的置信区间和病灶 AUC 条件通过，仅宿主 Dice 增益条件未通过。当前保存状态是 `STOPPED_AT_G1`，新统一 Stage II/III 没有启动。原门、权重选择、观测、预算及失败结果保持。

两维 G1 都是伪参照工程读出，不是最终分割或病灶检测结果。比较训练后模型与随机骨干，也不能单独归因出本次 2048 步的净效果：其中包含旧 SSL 初始化的贡献。若要解释“新统一训练带来了什么”，需另登记对 warm-start step0 的受控比较；该比较不能改写原 G1，也不默认新增完整随机预训练臂。

### 2.3 三个最终目标仍然存在的缺口

| 目标 | 独立 2D | 3D |
|---|---|---|
| A32 | 模型接口已支持；新统一监督模型尚未训练与验收 | 旧完整模型仍有五类缺失；13-host 汇总不能证明全部 32 类成功 |
| U 实例 | 平面监督及 weak-R 资格已实现；没有完整二维质量结果 | 旧完整模型低误报检出仍失败；query 解码改动没有解决总体问题 |
| R13 + no-host | 有 TRAIN 几何弱监督；held-out 平面参照与评价尚未接通 | 历史受控 ABA 0.568436，低于同模型解剖查表 B0 的 0.698324 |

这里的旧模型结果不是新统一模型的实测质量。旧数据截断问题已经修复，也不代表其它来源的误报和 A/R 问题随之解决。

当前推理 loader 只接 format1 技术导出，正式训练导出为 format2；旧 evaluator 不直接消费新 validation 角色；周期验证主要是 loss。因而后续即使 G1 通过，也还需要能直接回答全部 A/U/R 问题的评价入口。

原生 DICOM 仍缺可信患者空间证据：已审 fastMRI 原件缺 IPP/IOP，候选 H5 对应不能补造 affine。Level R 数据库有 1297 个病灶，但医生 labels/adjudications/releases 均为 0。几何弱标签结果不能充当医生结论。

## 3. 对当前路线的判断

工程基础已能支持进一步实验；用户目标仍没有完成。眼前的阶段阻塞是二维 G1，但项目风险也包含完整 A/U/R 失败、评价接口缺口和最终医学参照不足。

已有大量诊断排除了部分直觉方案：仅单调校准既有分数、简单更换残余实例评分、将局部背景配额改成全局配额，都没有形成足以推进的统一修复证据。继续无限扩展这类探针，不保证产生更好的模型。

建议把下一轮组织成有边界的“诊断→一个干预→真实开发评价→继续或停止”循环。每个实验必须说明它能改变哪项决策、测量哪个 A/U/R 终点、何时收尾。代码正确性与指标进展分别报告。

## 4. 可选路线与推荐

| 路线 | 好处 | 代价或风险 |
|---|---|---|
| A：先把全部精力放在二维 G1，过后再建设最终评价 | 保持当前门控顺序，短期任务单纯 | 可能反复追逐线性读出，监督训练结束后仍缺完整评价 |
| B：补齐评价入口，同时对二维做有限诊断；保留 G1 后再监督训练 | 下一模型能被直接检验，诊断与终点相连 | 两条工作有接口协调成本；需要明确每项诊断的停止条件 |
| C：另立协议直接以监督任务决定 SSL 是否值得保留 | 更直接检验任务表现 | 改变已批准的 SSL-first/G1 规则，失去当前阶段可比性；须单独设计和用户决定 |

**推荐 B。** 不自动采用 C，不降低 0.05 门槛、不改选 checkpoint，也不把重复 G1 当提高成绩的办法。若有限实验仍不能支持当前表征路线，再提交清晰的路线变更比较，保留这轮 FAIL。

## 5. 后续顺序与每步交付

### 第一步：把终点评价补齐，并完成一次已有证据诊断

两项可以独立推进，均不需要启动正式监督训练。

**评价：** 在已有 10-21 草稿基础上接通 format2 II/III 导出与完成证书、新开发验证角色、两种输入模式和原网格输出。先用合成 tiny 模型验证接口，不能用合成指标声明真实质量。Stage I 骨干不能伪装成完成监督训练的模型。

每个模式分别报告 A32 各类支持与 Dice、13-host 汇总、U 检出与误报、受控 R、端到端 R，以及同病灶同观察的几何查表 B0。二维用 FP/image 和面积，三维用 FP/scan 和体积；不跨分母合并。验证平面按标签/预测无关的既定规则冻结。几何 R 评价单列 NOT_EVIDENCE，不将 validation 改标 TRAIN 来复用训练资格。

**二维诊断：** 首先复用原 checkpoint、特征缓存、日志与源码。回答适配器和共享参数是否更新、是否存在退化特征、宿主各类支持与错误集中在哪里、训练与读出是否存在会改变输入含义的不一致。当前源码两处均按完整原始平面归一化，不能只凭“输入不一致”猜测认定 bug；裁块/选择差异要区分设计差异和缺陷。

本步交付一份有限结论：已排除什么、证实什么、唯一优先干预是什么，或证据不足需比较哪两个机制。首轮不重新拟合读出、不挑选 plane/阈值、不补跑已有 GPU 测量。若关键证据未保存，可登记一次受控新增测量及其限制，不能声称缓存已证明因果。

**验收：** 接口合成端到端通过；匿名诊断可复算；原 145 个执行源码承诺与保存结果不被重写；新报告明确“接口可用”与“尚无监督 checkpoint 可评估”的边界。

### 第二步：针对二维表征开展有上限的实验

建议默认最多两轮有预算的候选干预，此限制是本文件的建议，不是已执行或已有用户决定。优先修实证错误；若没有错误，依据证据从适配器优化、二维 SSL 目标或两维曝光分配中只选一个主要因素。不得凭“差 0.00645”直接断言训练步数不足。

每轮启动前冻结初始化、改动、两维观测/曝光、学习率、步数或墙钟上限、读出与失败处理。修改配方后建立新 run，不覆盖或假装续跑旧正式 run。开发用评估可以复用已暴露开发集但要声明适应性；正式阶段门仍用冻结的完整配方，保留两维全部结果，历史 test 不参与候选选择。

阶段门继续检查两维，另看三维是否因新二维训练退化。通过时输出一个可严格继承的骨干及 G1 记录；两轮均无支持时交付比较结论，重新讨论表征或门协议，不继续无边界扫参，也不自动绕过 G1。

### 第三步：先证明监督任务学得动，再执行有界 II/III

在两维 G1 通过后，从同一骨干依次进行短 TRAIN 监督能力检查和正式 II/III。每个模式用冻结、包含有效 A/U/R 目标的小集合，证明真实 A 类、异常实例与合格宿主预测可以学到，而不只看总 loss。小集合成功是优化可行性，不是泛化。

开跑前先核对 Stage II 主干学习率。历史高主干学习率曾冲掉 SSL 解剖表征；当前首轮登记又列 Stage II backbone 5e-4、仅前 1000 步乘 0.1。两种设置不能直接判定同效，但存在已知风险。新计划须明确其选择依据，先做有限保持性/监督学习检查，不能不加论证复制高主干学习率。旧 Q25 第 1000 步数值不可直接套用于新数据/配方。

短检查有有限且预先冻结的预算、有效类别与病灶支持、各任务损失/预测指标及拒绝继续的条件；具体样本数和阈值由下一实施计划在读取结果前确定。若 A/U/R 中一项连 TRAIN 都学不会，就在对应模块纠正，不直接消耗完整正式预算。

正式 II/III 的预算根据上述曲线与资源测量登记，保留两维曝光、来源分布、权重选择和恢复。周期验证除 loss 外使用第一步的任务指标。超出预算而未收敛须明确报告，不能把第一个小预算 pass 当成已充分训练。

### 第四步：按 A/U/R 的失败原因作有界修正

下一完整模型先在开发集给出 2 模式 × 3 任务的结果，再决定单一主改动；每轮不要求同时改善所有任务，但必须检查另外两项的退化。

- **A：** 按全部 32 类检查支持、采样、预测概率及类竞争；13-host 均值达标但结构塌掉时，不能声明 A32 完成。
- **U：** 若 query 实例学习在正确数据和有限优化检查下仍不成立，比较已登记的“语义异常分割 + 连通块实例化”退路，事件特征从组件池化，保留 R 输入。旧 N7 的 60k 迭代触发条件不适用于新短预算，启用前重新冻结判据和预算并交用户确认。此退路满足 U 输出目标，但不是已经验证有效的修复。
- **R：** 用相同观察/实例的 B0 比较受控绑定，再看 U 检出后端到端成功率。coarse 与 dense 预测几何来源可作独立受控对照；分开替换 A/U 几何以区分贡献。冻结 R 头对新特征的结果只能诊断输入敏感性，架构优劣需匹配训练后评价；不以 logits 改变或检出覆盖增加声称 R 头变好。

不直接复用跨原生网格/重采样分布的旧 S7 数值作为新二维门；要在可比观察、患者与 FP 预算下建立对应基线。若受控 R 始终不优于查表，报告关系模块无增益并提交方案选择，不能因为原提案存在显式关系模块就强行维持其贡献主张。

### 第五步：准备最终独立证据与 DICOM 验收

这条线需要外部资料或真实读者，可在训练前准备，但不阻塞现有合格 NIfTI 的工程能力实验，也不因工程实验推进而从最终交付中删除。

- 核验上游 DICOM 的位置/方向、尺度与逐帧来源，使 A/U 回到原图并保留完整原字节和元数据；不为缺失几何猜造 affine。只声明实际验收的对象类型与输入范围。
- 已暴露历史 test 继续保留既有结果。开发选择结束后，用真实可证明独立的患者队列或事先封存的合格队列评价；同患者的新切片或新序列不是新测试患者。若现有资产不能证明独立性，明确该最终证据仍缺。
- 为用户指定读者准备 Level R 盲法、工作副本、分歧处理和一致率；没有明确指令不联系外部读者。实际医生标签和封存由真实工作产生。
- 验证二维、三维各自的 A/U/R，模型稳定后再做网页/API/URL。工程演示不能替代上述评价。

## 6. 验收口径：继承与待定

三维工程主门沿用已批准规格：13-host 平均 Dice ≥0.80；U 各来源在同误报工作点的灵敏度至少为相容 nnU-Net 基线减 0.05；受控 ABA(R) ≥同观察 B0。它们属于伪参照门，不能升级为临床认证。

新增二维最终数值门、A32 各类失败的明确接受政策、二维医学 R 的合格参照尚未齐备。下一实施计划可先实现并测量完整指标；在正式质量裁决前，必须将未定阈值/可见性/样本支持写清并审阅，不能看完结果后挑标准。缺参照记 unavailable，未知不是 no-host。未定临床门不妨碍工程评价接口或 TRAIN 优化检查，但阻止声明最终能力已达标。

## 7. 约束、实施者裁量与本轮完成条件

沿用 PyTorch/nvgen、现有模型和数据实现、患者分区与隐私规则。医学生成物只在许可私有输出根，原数据只从 `/data2/congcong/data/FM_data` 读。GPU 使用已有授权，先看实时负载与可见性，保留已有任务。CPU 测试隐藏 CUDA、nice19、限制线程；按改动做回归与独立审阅。

实施者可决定模块/CLI 名称、合成 fixture 和缓存约简细节；不得自行改功能范围、阶段顺序、原 run 门槛或将几何参照改称医生真值。预算、数值干预和新增验收门在下一实施计划登记，当前建议不是启动命令。

本轮完成条件是交付本设计、独立 builder check 及用户可评判的顺序；不是完成模型修复。用户认可本路线后，按 brainstorming 约定进入 writing-plans，把第一步和第二步展开为具体任务/命令/验收。若用户只要求本次分析，则本文件和对话建议就是本次交付。

独立 builder check 已完成，结论为“nothing important left”。该检查判断文档能否据以规划，不是代码审查、新实验或医学质量评价。本次文档核对本地链接与工作区变更范围，不重新执行训练或测试。
