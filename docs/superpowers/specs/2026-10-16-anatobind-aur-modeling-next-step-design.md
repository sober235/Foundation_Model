## 4. 第一项工作：固定六例，复现原路径

沿用既有 NEXT_STEPS 的确定性选例规则：BMSR/T1c、ISLES/DWI、PDGM/FLAIR 各两个不同 val 患者；有 U 监督且至少一个非 ignored GT。对 `[0, source, patient, case, sequence]` 用 `json.dumps(..., ensure_ascii=False, separators=(',', ':'))` UTF-8 无换行序列化，按 SHA256 十六进制值排序，身份元组打破平局；每组取前两个不同患者。先冻结清单，再看图；病例清单本地保存，对外只记来源数和哈希。验证名单以外患者不得进入。

固定 checkpoint：`derived/aur/ssl_runs/c2_stage3_80k_20261014_1344/aur_stage3_best.pt`；SHA256 `38f6376333041a75be1cce83e927bc221468761f80ae952e2a3020805f7dcbde`。固定清单 SHA256 `fb96acd741aa6c0ee689eb772a4332304501c8d63ebd7ccddcd657f41eb86d5d`、crop `[128,160,160]` 和原推理精度、窗口、阈值、有效区域及加权规则。原运行基线代码 `77fd6eb`；诊断代码需要单独记录 diff 与 SHA。

先重现原始整卷滑窗，GT 不参与选窗。观察代码不得改变模型输出；原设置下的连通块数、排序后的框与体素数必须完全相同，体积绝对容差 `1e-3 mm³`、score 容差 `1e-5`。任一不符，先排查输入/权重/精度/设置，不进行模型原因归因，不事后放宽容差。

资源建议沿用既有草案：一张确认空闲的 GPU，首例计时测峰值内存，顺序运行，六例回放总上限两小时；超限保留已得证据并报告。此上限不代表已实测耗时，也不授权抢卡。数据只读 `/data2/congcong/data/FM_data`，新诊断输出写独立目录，不覆盖历史产物。

## 5. U：在同一路径上区分三种损失

实际路径为：每窗 U query masks → presence > 0.5 → query 最大概率并集 → Gaussian 加权跨窗平均 → 概率 ≥ 0.3 的 26 连通块 → 10 mm³ 体积过滤 → 连通块平均 score 过滤。

每个窗口保存 `(window_id, query_id)`，观察前后的原始预测。局部完整数组仅本地保存；公开只用匿名汇总。

1. **单 query 是否已经能分出病灶。** 对原滑窗中的每个 GT，记录覆盖度、全部 query 的局部 mask IoU、病灶内外概率和 mask 体积；主比较统一采用 `>= 0.3`，另列 `> 0.5` 用于解释旧 oracle，不搜索阈值。单 query 的局部统计不称为整卷检测灵敏度。
2. **presence 是否丢掉有用 query。** 在相同窗口、相同 mask 阈值和相同 GT 区域内，比较全部 query 与 presence > 0.5 子集的最佳 IoU及其分数；明确记录有用 query 在哪一步被去除。观察性去门结果只作 oracle，不替换模型结果。
3. **合并是否毁掉可用的实例信息。** 分开记录选中 query 的 masks、每窗 max、跨窗分子/分母、最终概率图及连通块。max 不会逐体素降低其输入概率，但可能加入假阳桥接并合并实例；加权平均可能因上下文分歧压低概率，尤其要记录无 query 通过但仍增加分母的窗口。记录体素 TP/FN、健康背景/其他真实病灶/ignored 区域的概率及 CC–GT 体素交集矩阵，结合框匹配判断实例是否被连接；不能用 bbox 包含代替 mask 重叠。不同窗口同号 query 不代表同一实例，必须保留窗口坐标和 query 索引。
4. **有效区域与评价控制。** 所有诊断都使用相同物理网格、valid/padding mask 和窗口权重；GT 在该窗口外的体素不加入局部 IoU。忽略病灶、26CC、10 mm³ 下限及 Hungarian 一对一 box matching 沿用原定义。合成的分离小实例经过测量/连通块代码应保持正确，观察器关闭时输出须与基线一致。逐体素窗口权重总和须覆盖原有效区域，重建的分子/分母必须还原原概率图。

训练点采样与 dense 推理使用同一完整分辨率 pixel head（`heads.py::masks`）；当前代码不能支持“点预测和稠密预测使用了两个不同头”的假设。若回到训练通路诊断，需要核查每个实例的采样、匹配与 dense 泛化，且 `u_supervised=False` 仍是整项 U loss 关闭，不能充作健康负例。

六例只定位机制，不证明总体性能。若这些例子不包含某类故障，应写“未观察到”，不能据此排除整个人群的机制。

## 6. A 和 R 同时保留自己的诊断

### A：分项观察，不能把宏平均临界通过当作完成

先读已有完整 val 的 source × sequence × host 及 32 实体分项，标注缺少的统计；六例回放额外观察病灶附近的 A 图、侧别和 presence。重点核查 val 已表现出的 ISLES、皮层、深灰短板。A loss 忽略病灶体素而 A 评价包含它们，需补报病灶内外误差，判断该监督差异贡献，不替换原指标。分开局部 Dice 与整卷 Dice、预测错误与 SynthSeg 参照可疑区域，不改 A 的结构词表或最终门。

后续只有看到证据才选单一变量：监督/网格错误优先修通路；训练可拟合而 val 源间差距大才研究采样或增强；训练本身不拟合才研究 A 优化/分辨率。不能因 test 差 0.0012 直接追加训练、改阈值或减掉难类别。U 改动后始终重新报告 A，避免共享主干回退。

### R：先核清“受控”路径真正给了模型什么

当前 controlled track 绕过整卷 U 检测和 score 过滤，但仍用 GT 中心裁块选择一个 U query；R 的几何来自该 query 的粗分辨率预测 mask 和粗 A 预测，并未自动替换成 GT U mask。B0 则用完整 GT 实例和整卷硬 A 图。因此“给定 GT 病灶”并不意味着两个方法看到了完全相同的几何信息。

先在已有 val 逐实例结果中按 local A Dice、query IoU、来源、大小和侧别分层，检查 R 的 harm 是否集中在低质量上下文。六例中保留 R 选中的 query id、A/U 几何输入、候选宿主、14 类概率与 B0 答案；核对局部裁块宿主目标与整卷目标是否一致，定位边界截断等标签问题。

只作诊断的 oracle 后续可逐项替换 U 几何或 A 几何，分清几何输入与关系头本身的损失；一次只替换一项，保持 token、候选词表和评价集合不变。使用 GT 的 oracle 永不算正式 R 成绩，也不能悄悄替换 G3。额外前向须计入回放预算；预算不足时先交付分层与输入核查，把 oracle 回放列为未做。

还要核查粗 mask 投影分支在 Stage II/III 获得什么监督和梯度：粗 mask 与正式 dense mask 的参数/分辨率不同，Stage II 粗投影冻结、Stage III 接收 R 的间接监督，不能假设 A/U 输出较好就意味着 R 所见的 mask 同样好。现有 local A Dice 来自整卷硬 A 图，不能代表 R 读取的粗、presence 门控 A。比较 GT/预测 U 几何、粗/全分辨率 A、presence 前后 A 只作逐项诊断。还应检查事件质心距离特征与目标的病灶最近距离规则、局部/整卷宿主规则的差异是否实际影响样本。当前这些都是代码提示的候选原因，不是已证明的 bug。

## 7. 观察结果如何决定下一轮模型工作

| 诊断结果 | 下一项最小实验 | 必须保留的目标 |
|---|---|---|
| 单 query 有效，presence 丢失 | 验证集上的一次固定存在性通路干预；再决定训练修正 | U 实例和原 R token 归属不变 |
| 单 query 能分离，max/平均/连通块阶段丢失实例 | 针对被定位环节的一次解码实验；先定义跨窗去重及实例与 R token 对应 | 不把多个异常的并集当“实例” |
| 单 query 本身定位差 | 固定少量 train 裁块做拟合/监督/匹配/梯度诊断；不先扩大预算 | U 仍为统一异常，不增加病种头 |
| R 的粗 mask、局部目标或输入质量解释多数 harm | 对被定位的上下文通路做一项修正，使用同一集合比较 | 仍每个 U 一个 14 类主宿主输出 |
| A 的特定源/结构存在可复现监督或优化问题 | 针对该原因的一项 A 实验，检查共享主干对 U/R 的影响 | 32 结构均保留，13-host 门不变 |
| 基线回放不一致或证据不能区分原因 | 修复复现条件或补最少观测，记录未定 | 不凭猜测启动完整新训练 |

如果单 query 路径在数据/监督/小样本拟合核查后仍无效，可研究原规格 N7 的“语义异常头 + 连通块 + 实例内特征池化”退路。它保留 U/R 目标但改变建模机制，需要单独设计并说明实例分离和 R token 来源。原文触发条件写的是 Stage II **60k iterations**；当前预算写的是 **240k seen crops**，两者不能互换，不能宣布自动触发。启用前按原规格先向用户说明并确认，不能悄悄切换。

每个修正先在 train/val 以单变量小实验检验。只有拟合/复现/val 结果支持时，才冻结下一轮训练契约：代码、输入哈希、seed、预算、早停规则及 A/U/R 指标一起登记。最终运行同时交付三项输出，任一门未过就如实记录；test 不用来挑阈值、改架构或筛改动。反复看过的历史 test 结果不称为新的独立确认。

## 9. 实现计划的边界与代码依据

本次形成建模研究设计，不写诊断实现或更改模型。后续实施计划需把选例、无扰动观测、回放、分层和归因分成可单独验证的任务；对一个自然窗口中的全部 query 直接缓存可能占用大量内存，实施者应以逐窗口写本地或流式汇总控制峰值，同时保留足够的原始数组核查。记录资源估算，不预先缓存六例全部窗口。

- `anatobind/aur/{dataset,targets,losses}.py`：监督标志、裁块实例、A 病灶忽略、匹配与采样。
- `anatobind/aur/heads.py`：完整/粗分辨率投影、点掩膜与 dense 掩膜。
- `anatobind/aur/infer.py`：自然滑窗、presence、max、跨窗平均、组件、GT 中心 query 选择。
- `anatobind/aur/{model,relation,train}.py`：R 的实际粗几何输入及各阶段可训练参数。
- `anatobind/aur/eval.py`：整卷 A、local A、controlled/end-to-end R 与 B0 的输入。
- `anatobind/eval/{matching,detection_metrics}.py`：固定的匹配和 ignored GT 规则。
